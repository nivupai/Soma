# Human protocol conformance and lineage

M20 extends the M19 declaration/seal schema without relaxing M19 synthetic replay
restrictions. `template` describes one registered existing pipeline, then
`freeze_cohort` binds the complete explicit participant/session/task/run membership
before execution. Cohort membership is scientific protocol evidence; actual input
hashes, acquisition evidence, permission context and execution environment remain
separate. Every selected unit remains in a plan and execution record, including
missing, ambiguous, unauthorized and failed units. No favorable subset is selected.

Conformance requires subject-level sampling, fixed dataset/version and scientific
methods, permitted task/partition, actual available resources, scoped private mapping
consistency, and content-bound use evidence. No scientific override, arbitrary
operation/import/shell or unsupported confirmation request is executable. A major
amendment does not itself implement or authorize a different scientific method.

Registered `human.bound-pilot` delegates to existing motor-imagery preprocessing,
epoch/QC and spectral code, or to fixed M10/M11 multi-Otsu predictions and physical
tissue scoring. Reference labels never fit prediction thresholds. Existing fMRI
inference and anatomical-readiness restrictions are unchanged. Raw BOLD stays blocked.

M18 graph/typed input fingerprints bind dataset, scoped subject, frozen protocol,
permission context, observed input content and exact environment. Private mappings
stay in memory; portable graph/provenance contains only opaque identity/fingerprint
fields. Keys never enter workflow context. Source inputs are rehashed at execution
boundaries. Native human execution schema v1.0.0 uses the existing M17
`experiment.manifest` envelope with metadata/small summaries and no linked arrays.
Readers check record/seal hashes, units, frozen cohort, status, environment, registered
methods, graph identity and identity/permission bindings before accepting evidence.

Human replay comparison reuses structural protocol comparison and seven drift
categories. It conservatively rejects incompatible subject/session/task alignment,
authorization changes, implementation changes and incompatible reference metadata.
Controlled changed input content is descriptive, not numerical equivalence. Human
numerical policy is frozen exact agreement for matching inputs; no bounds were
widened. Comparisons never authorize current data use, cache interchange, prospective
replication, biological drift or human reliability. Fresh use checks remain necessary.
