# Repeated execution records

`soma.protocol.execution/1.0.0` binds a local seal, snapshot, workflow/implementation,
actual environment, explicit positive sequence, UUID, actual UTC start/end,
parameters/seeds through graph evidence, QC observations, all unit outcomes,
missingness, deviations and result content/file fingerprints. The native container
is the existing M17 `experiment.manifest` result envelope (1.0.0/1.1.0 supported by
Soma); protocol execution payloads contain metadata and selected finite numerical
summaries, with no linked arrays. Reading rejects array-bearing execution envelopes
before materialization. The existing scientific arrays stay in private M18 caches.

`history` sorts explicit sequences, rejects duplicate IDs/sequences and refuses to
pool different study IDs. `append_history` locks an explicit private study root and
requires a new increasing sequence; an existing execution destination is immutable.
File names do not prove temporal ordering. Hashes are local integrity evidence, not
authenticated participant identities or independent provenance attestations.

Deviations include category, stage, original policy, observed behavior, evidence,
scientific consequence, resolution and any amendment reference. Missing units retain
their denominator. Unsupported conductivity, inference overrides, geometry/ontology
mismatches and partial stages cannot silently become compliant.

Current examples are independent synthetic realizations and repeated computational
executions. They are not longitudinal human measurements. Real participant sessions
require an implemented identity/session/task/permission adapter, which is unavailable
in this release. Historical audit evidence stays INDETERMINATE where binding or
independent timing evidence is absent. Original reports are preserved unchanged.
